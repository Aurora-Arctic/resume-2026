# Experience — Implementation Record

This document is a transcript of the work done around `src/components/Experience` — the work-history section. See [RESUME.md](RESUME.md) for the shared section-order, data-model, and layout-flexibility decisions behind this whole batch of scaffolding work; this document covers only what's specific to `Experience`.

## Why it exists

The core section of a technical resume per every source consulted (bridgeviewit.com and general search): reverse-chronological work history, one entry per role, each with a company/title/location/date-range header line and bullets following an "Action + Tech + Impact + Scope" pattern. Scaffolded now with one placeholder entry in `resumeData.experience` (`src/data/resume.ts`) so the real bullet-writing work (a separate task) has a working component to fill in.

## Current state

- `index.tsx`: takes `experience: ExperienceEntry[]`, maps each entry to an `<article>` inside a `<section aria-labelledby="experience-heading">` — `<h3>{title}</h3>`, an italic company line, an italic meta line, then a `<ul>` of `bullets`.
- `index.scss`: spacing between entries and the meta line only, no other visual treatment.
- `index.test.tsx`: renders one sample entry, asserts the composed `<h3>` text, the meta line, and a bullet all render.

## Side-by-side with Projects, row-aligned to each job, sticky + fade (2026-08-10)

User request: put `Experience` and `Projects` side by side on desktop (mirrored into Full/Summary/Minimal print, linear only in Application), with each job's row in `Experience` aligned exactly to that job's project group in `Projects`, and — specifically the `Experience` side only, not `Projects` — the current job entry stays pinned in view (`position: sticky`) while the user scrolls past its (possibly much taller) paired project group. Full cross-component design (subgrid choice, wrapper, row-count math) lives in [RESUME.md](RESUME.md)'s transcript; this entry covers what changed specifically in `Experience`.

**New `hasPersonalProjects: boolean` prop.** One of the eight original projects (Design Bright) has no associated job — `Projects` groups it under the literal company `'Personal'`. For that group to have a row to align with in `Experience`, `Resume` computes `hasPersonalProjects = data.projects.some(p => p.company === 'Personal')` and passes it down; when true, `Experience` renders one extra trailing row: `<h3 className="resume-experience__personal-label">Personal Projects</h3>` — no location/dates/bullets, just a small heading-style label, per the user's explicit "no label needed beyond a heading" answer.

**Per-entry `gridRow` via array index, not filtered/compacted.** Each entry (and the trailing Personal Projects row, if present) gets an inline `style={{ gridRow: index + 2 }}` (row 1 is the `<h2>` heading). This has to be the _raw_ index into the `experience` array, computed before any filtering — `Projects` computes its own groups the same unfiltered way (`companyOrder.map(...)`, not `.filter(...).map(...)`) so a row index always means the same job position on both sides, even in the (currently hypothetical) case of a job with zero matched projects.

**The `.resume-experience__row` wrapper — added specifically to fix a sticky+scroll-driven-animation interaction bug.** The first implementation put `position: sticky` and `grid-row` directly on `.resume-experience__entry` (the `<article>` itself). That works fine for the sticky pinning alone, but broke the fade animation (below): `animation-timeline: view()` on the sticky element itself measures the _subject's own_ un-stuck box — which, with `align-self: start`, is only as tall as the entry's own content, not the full (often much taller) row it shares with its paired `Projects` group. The reported symptom was the fade only ever kicking in once the _entire_ `.resume-experience` section had nearly finished scrolling, not per-row. Fix: each entry is now wrapped in a `.resume-experience__row` div that carries the `grid-row` placement instead of the article, and is left `align-self: normal` (default `stretch`) so it fills the _entire_ subgrid row height, non-sticky. `Experience/index.scss` gives this wrapper `view-timeline-name: --resume-experience-row` (feature-detected via `@supports (animation-timeline: view())`), and the _inner_ `.resume-experience__entry`/`.resume-experience__personal-label` (still `position: sticky; top: 1.5rem`) reads its animation progress from that named timeline via `animation-timeline: --resume-experience-row` instead of a self-referential `view()`. Named view-timelines are exactly built for this "trigger element ≠ animated element" split.

**The exit-fade window — also had to move off the "exit" named range.** With the row-wrapper fix in place, `animation-range: exit` still fired too early: for a row taller than the viewport (any job with several bullets/projects — the common case here), the "contain" phase it's measured against (the row fully covering the scrollport) spans most of the scroll-through, so the named "exit" range starts as soon as the row's bottom edge is merely _approaching_, well before the entry is actually about to release. Landed on an explicit fixed-length range instead — `animation-range: cover calc(100% - 8rem) cover 100%` — so the fade only plays out over the last `8rem` of scroll distance before release, regardless of how tall any given row is. (The `8rem` figure came from live visual tuning against the dev server, not a formula — adjust it directly if a future content change makes it look off again.) Verified with an ad-hoc Playwright probe (`getBoundingClientRect()` + `getComputedStyle().opacity` sampled at 10px scroll increments) that opacity ramps smoothly from `1` to `0` across that window and lands at `0` at (or just before) the point where the entry has fully scrolled out from under its sticky pin — see [RESUME.md](RESUME.md)'s transcript for the full verification pass across desktop, mobile, and all four print tiers.

**Feature-detected, not print, respects reduced motion.** The whole `sticky-exit-fade` mixin is wrapped in `@supports (animation-timeline: view()) { ... }` — browsers without scroll-driven animation support (Safari/Firefox lagged Chrome here as of writing) just keep the plain `position: sticky` behavior with permanent `opacity: 1`, no fade. It's also screen-only (nested inside the `min-width: $breakpoint-desktop` block, never mirrored into `grid-print-tiers`) since a paginated print context has no scroll to drive it, and disabled under `@media (prefers-reduced-motion: reduce)`.

## Split company onto its own line, date-first meta, trimmed Alma title, real bullet content (2026-08-10)

User request: put date and location on a separate line with date first (was `{location} — {startDate} to {endDate}`, now `{startDate} to {endDate} — {location}`), pull company onto its own line separate from the title (was a single `<h3>{title} · {company}</h3>` heading), drop "for Developer Experience" from the Alma title/bullet (redundant with the section context), and replace the placeholder single-bullet entries with real content the user supplied directly.

**Markup**: `index.tsx`'s heading split from `<h3>{title} · {company}</h3>` into `<h3>{title}</h3>` followed by a new `<p className="resume-experience__company">{company}</p>`, modeled directly on `Projects/index.tsx`'s existing `resume-projects__company` line/pattern. Unlike `Projects`' version — which is `display: none` on desktop/print-grid tiers because row-alignment with `Experience` already conveys the company there — `Experience`'s own `&__company` rule (`index.scss`) stays visible in every layout, since it's the source of truth the `Projects` alignment depends on.

**Content**: Alma's title dropped "for Developer Experience" (`Senior Backend Engineer & Technical Lead for Developer Experience` → `Senior Backend Engineer & Technical Lead`), trimmed the same phrase from the one bullet that repeated it, and gained five more user-supplied bullets (CI/CD and client-data-protection work first, then partner integration and developer-experience leadership, then mentorship, with the promotion bullet moved to the end per explicit reordering feedback). 14Four gained a bullet about the self-service site-creation framework, placed first per the same kind of reordering feedback. Uxiliary's one placeholder bullet was fully replaced with three bullets covering technology adaptability, customer system integrations, and community-building — the user's "Replace" instruction, unlike Alma/14Four's "Add."

## Bullets hidden on Summary/Minimal print tiers, per-entry summary, ellipsis indicator, bolder company line (2026-08-10)

User request, scoped to `Experience` only (explicitly confirmed not to extend to `Projects`, whose own `__company` line is already `display: none` on non-linear print tiers so the same styling ask didn't apply there): hide the bullets list on the Summary and Minimal print tiers, replace it with a short prose summary specifically on the Summary tier (drafted by the assistant from each entry's bullets, iterated through several rounds of user review/edits before being approved as final content), mark the omission with an ellipsis on both tiers, and restyle the company line to be larger, bold, non-italic, sitting tighter under the heading with more space below it.

**Data**: added an optional `summary?: string` field to `ExperienceEntry` (`src/data/resume.ts`), populated for all three entries with the user-approved condensed text.

**Markup**: reused the existing `print-hide-summary`/`print-hide-minimal` utility classes (`src/scss/_print.scss`) directly on the bullets `<ul>` — the same mechanism `Skills` already uses for its sub-lists, so no new SCSS mixin was needed. Added a conditional `<p className="resume-experience__summary">` (only rendered when `entry.summary` is set) and a `<span className="resume-experience__bullets-ellipsis" aria-hidden="true">…</span>`, modeled directly on `Skills`' `resume-skills__sub-list-ellipsis` pattern (comment, `display: none` baseline, `@media print` tier-gated override).

**Tier behavior**: Full and Application still print the complete bullet list unmodified. Summary hides the bullets, shows the `&__summary` paragraph, and shows the ellipsis. Minimal hides the bullets and shows the ellipsis, but — per the user's explicit choice — gets no summary text, just the omission marker.

**Company line restyle**: dropped `font-style: italic`, added `font-weight: 700` and `font-size: 1.125rem`, and changed `margin` from `0.25rem 0` to `0 0 0.75rem` so it sits flush under the heading (which already carries its own bottom margin from the shared `_typography.scss` heading rule) with more separation from the meta line beneath it.
