# Ad-hoc Playwright verification

## Why this doc exists (2026-08-09)

While visually verifying a Skills-section tooltip placement change via a scripted headless-browser screenshot, I repeatedly hit the same two dead ends before landing on a working approach: first looking for a `chromium-cli`-style driver tool (referenced by the bundled `run` skill's browser-driven example) that doesn't exist in this repo or its containers, then writing the driver script into the session's scratchpad directory (outside `/app`) and hitting `ERR_MODULE_NOT_FOUND: Cannot find package 'playwright'` — Node resolves a bare specifier like `'playwright'` relative to the _importing file's own location_, walking up its `node_modules`, not relative to the shell's `cwd`; a script outside the project tree has no `node_modules` in its ancestry to find. Setting `NODE_PATH` doesn't fix it either, since that only applies to CommonJS resolution, not ESM.

The working pattern: import `chromium` from the `playwright` package (already a project dependency for `test:e2e`) directly in a small script, launched with `{ args: ['--no-sandbox'] }` for the sandboxed container, and — critically — write that script inside `/app` (even if just a throwaway file deleted right after) rather than a scratch directory elsewhere. The user asked for this to be written up after watching the same debugging cycle repeat, and asked specifically that it live somewhere other devs using this repo would see it too, not just in my own session memory — hence `claude-docs/PLAYWRIGHT-ADHOC-VERIFICATION.md` plus a pointer from `CLAUDE.md`'s Testing section, rather than (or in addition to) a private memory note.
