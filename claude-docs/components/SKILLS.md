# Skills — Summary

Full implementation history: [claude-docs/transcripts/components/SKILLS.md](../transcripts/components/SKILLS.md)

- Renders categorized technical skills from a `skills: SkillCategory[]` prop (each entry: `{ category: string; skills: SkillEntry[] }`, `SkillEntry = { label: string; subItems?: string[] }`) — every skill is the same object shape, `subItems` simply absent when there's nothing to expand.
- Uses a `<dl className="resume-skills__groups">` — category as `<dt>`, a `<ul>`/`<li>` of individual skills as `<dd>`'s content. Laid out as a 3-column grid at `$breakpoint-desktop` on the web; single-column stacked below that breakpoint and always in print (per the site's standing print rule).
- Diamond bullets are shared, not Skills-specific: `src/scss/_typography.scss`'s default `ul`/`li` rule (see [LAYOUT-SETUP.md](../LAYOUT-SETUP.md)) provides the absolutely-positioned `li::before { content: '◆' }` (list's own `list-style` removed) rather than `::marker`, since `::marker`'s allowed-property list excludes positioning — `::before` was needed to nudge the glyph's vertical alignment. Colored `$wine`/`$grape-press` (dark/light theme split, low-contrast-avoidance same as links) inside `_typography.scss` itself. `Skills/index.scss` only adds its own tweaks on top (sub-list margin/font-size) and the expandable-arrow suppression below. `dt` is bolder/larger (`font-weight: 500`, `1.125rem`, matching the site's `h4` rung) than `dd`'s inherited body text, to visually separate category labels from their skill lists.
- A `SkillEntry` with `subItems` renders as an expandable item instead of plain text: a `<button aria-expanded aria-controls>` wrapped in a `Tooltip` ("Click for more info", hover/focus-triggered like every other tooltip on the site), toggling an always-DOM-mounted `<ul hidden={!expanded}>` of sub-items below it. The bullet swaps from diamond to `▶`, rotating to `▼` (via a `--skill-arrow-rotate` custom property) when expanded; hovering/focusing the toggle recolors both the label text and the arrow to the diamond's own color and scales the arrow up 20% (`--skill-arrow-scale`), on the same `$theme-transition-duration`/`$theme-transition-easing` timing used everywhere else on the site. Print ignores expand state entirely — the `hidden` sub-list is forced visible and the arrow reverts to a plain diamond, since the printed resume always shows full detail.
- The toggle button's hit box is wider than its visible label: `margin-left: -1.25rem`/`padding-left: 1.25rem` pull it into the `<li>`'s bullet gutter so the arrow (rendered via `::before` at the button's left edge) is part of the button's own clickable area rather than a separate, unclickable `li::before`. At `$breakpoint-desktop` this gutter sliver overlaps where the tooltip's hover-persistence bridge lands once hovering the button reveals it — `.resume-skills__skill-toggle` carries `z-index: 2` (above the tooltip's `z-index: 1`) so the button, not the bridge, wins hit-testing there and the arrow stays clickable while its own tooltip is showing (see the transcript's 2026-08-10 entry for the full repro).
- Dismissing (×) any one expandable skill's tooltip clears every skill tooltip in the section at once, via `Tooltip`'s `onDismiss`/`dismissTooltips` extension — see [TOOLTIP.md](TOOLTIP.md). Distinct from `RestoreTooltips`, which is site-wide and goes the other direction (restores, doesn't dismiss).
- Tooltip placement (`.resume-skills__skill-tooltip`, per-instance CSS — placement is always the caller's responsibility, see TOOLTIP.md) is mobile-first: below `$breakpoint-desktop` it sits above the skill item, left-aligned with the item's own left edge, downward-pointing arrow; at `$breakpoint-desktop` and up it moves beside the item instead — to its left, vertically centered on the label text, arrow on the tooltip's right edge pointing back at the trigger.
- Placeholder categories in `src/data/resume.ts` are already tailored to a backend/serverless/DevEx profile (`Languages`, `Cloud & Infrastructure`, `CI/CD & Tooling`, `Frameworks & Libraries`) since the category labels are structural, not content — the actual skill items inside stay generic placeholders.
- Fifth section rendered by `Resume` (after Projects, before Education) — see [RESUME.md](RESUME.md) for the overall section-order/data-model/layout rationale shared across all six sections.
- Sub-item lists opt out of the Summary, Minimal, and Application print tiers (`className="resume-skills__sub-list print-hide-summary print-hide-minimal print-hide-application"`, see [PRINT-OPTIONS.md](PRINT-OPTIONS.md) for the tier mechanism) — only Full still prints every sub-item. This wins over `index.scss`'s `@media print .resume-skills__sub-list[hidden] { display: block; }` (which otherwise forces sub-items visible in print regardless of on-screen expand state) purely on CSS specificity: `html[data-print-mode='summary'] .print-hide-summary` is one type selector ahead of `.resume-skills__sub-list[hidden]` with an equal class/attribute count, so it wins without relying on source order.
- A sibling `<span className="resume-skills__sub-list-ellipsis" aria-hidden="true">…</span>` stands in for each hidden sub-list, so condensed print output shows a cue that more detail exists rather than a silent gap. `display: none` by default (on screen and in Full print); the Summary and Minimal tiers show it in `$wine`, and the Application tier shows it in `$print-text` (dark gray, suitable for ATS submission without color).
- Each category's top-level skill _count_ is separately capped on the Summary (first 5) and Minimal (first 2) print tiers — independent of the sub-item hiding above. `Skills`'s render maps each group's skills with its `index`, applying `print-hide-minimal` (`index >= 2`) and/or `print-hide-summary` (`index >= 5`) via a new `className` prop threaded through both of `SkillItem`'s return branches. Since the cutoff is data-dependent (a category doesn't get a `…` unless it actually has more skills than that tier shows), the `group.skills.length > limit` comparison lives in `index.tsx`, not SCSS — two `SUMMARY_SKILL_LIMIT`/`MINIMAL_SKILL_LIMIT` (5/2) constants at module scope. Two per-category ellipsis `<span>`s (`resume-skills__truncate-ellipsis--summary`/`--minimal`) render after the `<ul>` only when that tier's own limit is actually exceeded — placed once regardless of tier, since truncated `<li>`s collapse via `display: none`, leaving the trailing span visually right after whichever item is last-visible.
