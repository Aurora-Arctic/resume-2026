# PrintOptions — Summary

Full implementation history: [claude-docs/transcripts/components/PRINT-OPTIONS.md](../transcripts/components/PRINT-OPTIONS.md)

- Hijacks Ctrl/Cmd+P (`preventDefault` on a `window` `keydown` listener) and adds a fixed top-right printer-icon button, both opening a modal that picks a print detail tier — Full, Summary, Minimal, Application — before calling `window.print()`. The browser's own File → Print menu can't be intercepted (JS has no hook for it) and falls back to Full detail, since no `data-print-mode` attribute gets set.
- Tier state is a `data-print-mode` attribute on `<html>`, mirroring `ThemeToggle`'s `data-theme` pattern — set right before `window.print()`, cleared on the browser's `afterprint` event. Every rule that reads it lives inside `@media print` (`src/scss/_print.scss`), so the attribute is structurally inert on screen regardless of value.
- **Mechanism only, not content**: `_print.scss` defines three independent classes — `.print-hide-summary` / `.print-hide-minimal` / `.print-hide-application` — that hide an element in that tier. There's no `.print-hide-full` (full = show everything, the no-attribute default). Assigning these classes to actual resume content is deliberately out of scope here; no section component or `resume.ts` was touched.
- `_print.scss` also exports two mixins: `linear-print-tiers`, scoped to the **Application** tier only, collapses `Resume`/`Skills`' desktop grid layouts to a single column; `grid-print-tiers`, scoped to every _other_ tier, reasserts that same desktop grid explicitly in print. The reassertion is necessary, not cosmetic — the grid normally only turns on via `@media (min-width: $breakpoint-desktop)`, but browsers evaluate a print media query's `width` against the physical page (Letter/A4, well under `$breakpoint-desktop`), not the screen viewport, so that breakpoint never fires on paper regardless of tier. Watch for this pattern elsewhere: any `@media (min-width: ...)` rule that's supposed to also apply in print needs an explicit `@media print` (or one of these mixins) reasserting it — it will not inherit from a screen-only breakpoint.
- Each tier has a one-line `description` shown under its label in the modal (e.g. Full: "All contents.", Minimal: "Just the essentials.") — part of the same `<label>` as the radio, so it's included in the option's accessible name. Tests that look up a radio by name (e.g. `getByRole('radio', { name: /^Full details/ })`) anchor the match to the label's start rather than hardcoding the full label+description string, or matching a bare substring — the Application tier's own description text ("Minimal details in a plain, linear layout.") happens to start with the same words as the Minimal tier's label, so an unanchored substring match hits both.
- The modal is a manually-built `role="dialog"` (not the native `<dialog>` element — its close can't be CSS-faded without `@starting-style`): `aria-modal`, `aria-labelledby`, a Tab focus trap, Escape-to-close, light-dismiss on backdrop click (via an `event.target === event.currentTarget` check, not `stopPropagation` on the panel), and focus returned to the trigger button on close. The backdrop is always mounted and toggled via `aria-hidden` + a `--open` modifier class, using the same opacity/visibility transition technique as `Tooltip` so it fades in and out instead of popping.
- The "Print" confirm button overrides the shared `_buttons.scss` fill to the _on-paper_ `$wine-dark` color (normally reserved for buttons inside `.paper-card`) even though it renders outside it, so it reads as one of the resume's own actions rather than page chrome.
- Icon is a hand-transcribed inline `<svg><path fill="currentColor" .../></svg>` copied from `@fortawesome/fontawesome-free`'s `svgs/solid/print.svg` — that package is a **devDependency only** (reference source for the path data), never imported at runtime, so no webfont/CSS bundle ships for one glyph.
