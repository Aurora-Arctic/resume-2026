# Resume — Summary

Full implementation history: [claude-docs/transcripts/components/RESUME.md](../transcripts/components/RESUME.md)

- Wrapper component (`src/components/Resume`) that assembles the six resume section components (`Header`, `Summary`, `Experience`, `Projects`, `Skills`, `Education`) in reading order from a single `data: ResumeData` prop.
- Rendered by `src/pages/index.tsx` inside `Layout`; owns the one `.resume` container used for page-level layout.
- Mobile-first single-column `flex-direction: column` stack, in DOM order, unchanged at every breakpoint (including print): `Header`, `Summary`, `Experience`/`Projects`, `Skills`, `Education` all stack top to bottom. An earlier iteration turned `.resume` into a two-column desktop/print grid that put `Header` on the right and `Summary` on the left, sharing a row — that swap was reverted; `Header` and `Summary` are back to a plain linear stack, `Header` first. `Experience`/`Projects` are still wrapped together (see below) and form their own side-by-side grid regardless, since that wrapper declares its own `display: grid` independent of `.resume`'s column count.
- `Summary`'s section (`.resume-summary`, `src/components/Summary/index.scss`) caps line length at `max-width: 69ch`, unconditionally — mobile viewports are already narrower, so no media query is needed. Added once `Summary` could stretch to the full card width after the two-column revert above.
- **`Experience`/`Projects` are wrapped in `.resume-experience-projects`**, a two-column (`1fr 1fr`) grid at `$breakpoint-desktop`, with `Experience` and `Projects` each set to `display: grid; grid-template-rows: subgrid; grid-row: 1 / -1`, sharing the wrapper's row tracks. `Resume/index.tsx` computes `companyOrder` (job company names in order), `hasPersonalProjects`, and `rowCount` (`1 + experience.length + (hasPersonalProjects ? 1 : 0)`), passing `gridTemplateRows: repeat(rowCount, auto)` to the wrapper inline (data-dependent, can't be known at SCSS-author time) and `hasPersonalProjects`/`companyOrder` down to `Experience`/`Projects` respectively. This makes each job's row exactly as tall as the taller of its own `Experience` entry or its paired `Projects` group — see [EXPERIENCE.md](EXPERIENCE.md)/[PROJECTS.md](PROJECTS.md) for the per-component row-placement/sticky details, and the transcript below for why subgrid was chosen over DOM-interleaving.
- **Print tiers**: Full/Summary/Minimal mirror the desktop grid (including the `Experience`/`Projects` subgrid pairing) via the `grid-print-tiers`/`linear-print-tiers` mixins (`src/scss/_print.scss`, driven by `PrintOptions`' `data-print-mode` attribute) — only the Application tier collapses everything back to a single top-to-bottom linear column, matching plain-text ATS parsing conventions. This is narrower than the project's original "print is always single-column, no exceptions" rule (see the transcript's 2026-08-09 entries) — that blanket rule was superseded once Full/Summary/Minimal started deliberately mirroring the desktop grid; Application remains the one tier that stays linear.
- Content comes from `src/data/resume.ts` (`resumeData`) — still placeholder values; each section's real content is filled in by later, individual tasks.
