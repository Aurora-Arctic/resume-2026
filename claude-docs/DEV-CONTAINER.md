# Dev Container / Sandbox Environment Notes

Operational gotchas specific to running Claude Code inside this project's sandboxed `/app` environment (the `devcontainer`/`testing` Docker stages, or an equivalent sandbox) — not implementation history, just things to do differently here than you might elsewhere.

- **Playwright's Chromium is pre-baked — never run `playwright install`.** `npx playwright install-deps chromium` fails (`install-deps` tries to `su` to root and the sandbox has no root password); `npx playwright install chromium` is also unnecessary. A chromium build already exists at `/ms-playwright` (e.g. `/ms-playwright/chromium-<rev>`), baked in by `Docker/Dockerfile.node`'s `testing` stage at image build time (see CLAUDE.md's Docker section). `npx playwright test` / `npm run test:e2e` find it automatically. If a Playwright run ever reports Chromium missing, confirm with `ls /ms-playwright` before investigating further — don't reach for an install command first.
- **No Python `yaml` module, and no pip install available.** `import yaml` raises `ModuleNotFoundError`. To validate YAML (e.g. GitHub Actions workflow files), use Node instead — a plain JS parse check, or `npx --yes yaml-lint <file>...` for real syntax checking.
- **Always verify with the coverage test variants, not the plain ones.** Use `npm run test:coverage` and `npm run test:e2e:coverage`, not bare `npm test`/`npm run test:e2e` — CI enforces an 80% coverage gate (see CLAUDE.md's Testing section) that the plain commands skip, and `npm test` alone doesn't run e2e at all. A plain `npm run test:e2e` can also pass on a stale `.cache` build from earlier in the session, which isn't a reliable signal the coverage variant will succeed.
  - Known caveat: `npm run test:e2e:coverage` forces a `gatsby clean` before rebuilding, which can hit a pre-existing LMDB `Invalid argument` error writing `page-data.json` in this sandbox (reproduces even on a clean `main` checkout with zero changes — see `claude-docs/transcripts/LAYOUT-SETUP.md`). If the coverage e2e run is blocked by this, say so explicitly rather than reporting a plain-variant pass as equivalent, and don't burn more than a couple of retries chasing it — it's a known sandbox condition, not something fixable via test or code changes.
