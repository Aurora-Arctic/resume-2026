# Docker / Dev Container — Summary

Full implementation history: [claude-docs/transcripts/DOCKER-SETUP.md](transcripts/DOCKER-SETUP.md)

- `makefile` wraps Docker Compose (`make docker-build|up|down|rebuild|logs`, targeting `Docker/docker-compose.yaml`) and mirrors the npm scripts one-to-one (`make npm-install|develop|build`, etc.).
- Two Compose services build from `Docker/Dockerfile.node` (multi-stage): `development` (`npm run develop -- --host 0.0.0.0`) and `devcontainer` (VS Code Dev Containers, runs as the `node` user). A `testing` stage in between bakes in headless-Playwright/Chromium deps for CI and local e2e — see [DEV-CONTAINER.md](DEV-CONTAINER.md) for sandbox-specific gotchas when working inside it.
- Both services bind-mount the repo root to `/app` and use a named `node_modules` volume — don't remove it, it prevents host-installed `node_modules` clashing with container-built native deps. `builder`'s `npm i` runs as `node`, not root; an `EACCES` on `node_modules` in the devcontainer means the volume is stale from before that fix — recreate it (`docker compose down -v`) rather than re-patching the Dockerfile.
- Both services also mount a per-service named `gatsby_cache_development`/`gatsby_cache_devcontainer` volume at `/gatsby-cache`, which `Docker/link-cache.js` symlinks into `.cache/caches-lmdb` (via `predevelop`/`prebuild`/`preanalyze`/`postclean` in `package.json`) — works around unreliable LMDB file-locking on the bind-mounted repo root. No-ops when `CONTAINER_CACHE_DIR` is unset, so bare-metal `npm run develop`/`build` are unaffected. See the transcript for why the cache lives one level deeper than `.cache` itself.
- Requires recreating the container (`docker compose down`/`up`, or `make docker-rebuild`) after this was added — a running container from before won't have the volume mounted, and `docker compose down -v` clears any now-orphaned `gatsby_cache` volume from an earlier iteration.
- `devcontainer` passes through `CLAUDE_CODE_OAUTH_TOKEN` (from git-ignored `Docker/.env`) so the Claude Code CLI is pre-authenticated; `make docker-up`/`docker-rebuild` regenerate it via `Docker/update-token.sh`.
- `devcontainer` also bind-mounts git-ignored `Docker/claude-home` to `/home/node/.claude` — a bind mount, not a named volume, deliberately, so it survives `docker compose down -v`. Create it yourself (`mkdir Docker/claude-home`) if missing, to avoid Compose auto-creating it root-owned.
