# Layout Setup — Summary

Full implementation history: [claude-docs/transcripts/LAYOUT-SETUP.md](transcripts/LAYOUT-SETUP.md)

- `Layout` (`src/components/Layout`) wraps every page: `.paper-chrome`/`.paper-card` shell, renders `ThemeToggle`, `BackgroundCredit`, and `RestoreTooltips`.
- Fonts: Lexend (body) / Syne (headings) — `$font-body`/`$font-heading` in `src/scss/_variables.scss`, applied globally via `src/scss/_typography.scss`. Self-hosted via `@fontsource/lexend`/`@fontsource/syne`, imported in `gatsby-browser.ts` (only the weights actually used in CSS: Lexend 200/400, Syne 400) — previously loaded from Google Fonts via `<link>`s injected by `gatsby-ssr.ts`'s `onRenderBody`, moved to self-hosting to eliminate the external request chain a PageSpeed Insights audit flagged; see "Self-hosting fonts instead of Google Fonts" in the transcript (supersedes that section's original "Moving the Google Fonts request out of the SCSS bundle" decision). Headings moved off the slab-serif `Bitter` to the geometric sans `Syne` — see "Replacing Bitter with a more angular heading font" in the transcript.
- `.browserslistrc` (repo root) targets `defaults and fully supports es6-module` — no config previously existed, so Babel (`babel-preset-gatsby`, `useBuiltIns: 'usage'`) fell back to browserslist's broad default query and polyfilled/downleveled for legacy browsers this site doesn't need to support, which is exactly the "unused JavaScript" a PageSpeed Insights audit flagged. See "Trimming legacy-browser JS via browserslist" in the transcript.
- Colors: `$wine-dark` (dark page background), `$silver-oxide`/`$lavender-oxide` (light-mode card background) — all in `_variables.scss`. Interactive-text colors (`$wine-stained`/`$wine-glow` dark-mode link/skill-toggle base+hover, `$wine-deep` light-mode base) were retuned against WCAG AA's 4.5:1 floor for their respective flat card background — `$wine-glow`/`$wine-deep` clear it; `$wine-stained` was manually tuned back down to ~3.86:1 for how it reads, a deliberate accepted tradeoff (`@media (prefers-contrast: more)`, below, covers users who need the stricter ratio). See the transcript's "Text/background contrast pass" entry for the full audit and per-token rationale. `$wine-drenched` is single-purpose again (print-only `Summary` `<strong>`) rather than shared across mismatched contexts.
- `@media (prefers-contrast: more)`: `.paper-card`'s two texture pseudo-elements (see below) dim further (`brightness(50%)` vs. the baseline `$texture-dim: 85%`), and links/the `Skills` toggle switch to the body-text colors (`$text`/`$silver-oxide`) plus a persistent underline instead of the wine family, so link identity doesn't depend on color alone.
- Print: `Layout/index.scss`'s `@media print` forces a plain white page and drops the card's shadow/padding/background; a separate `@page` rule sets size/margin. `src/scss/_print.scss` (a fourth shared partial, see below) layers on both a link-URL reveal and the print-tier mechanics PrintOptions drives — see [components/HEADER.md](components/HEADER.md), [components/BACKGROUND-CREDIT.md](components/BACKGROUND-CREDIT.md), and [components/PRINT-OPTIONS.md](components/PRINT-OPTIONS.md).
- `.paper-card`'s two "Prism" background textures each live on their own pseudo-element — `::before` (dark, always-on) and `::after` (light, opacity-crossfades in on `html[data-theme='light']`) — rather than as `.paper-card`'s own `background-image`, so `filter: brightness()` can dim the texture layers without also dimming the card's actual text/content. See [components/BACKGROUND-CREDIT.md](components/BACKGROUND-CREDIT.md) for the texture's attribution.
- Every component owns a colocated `index.scss`; shared cross-component CSS lives in `src/scss/` (`@use`d, not the deprecated `@import`): `_variables.scss` (tokens only — colors, timings, fonts, `$breakpoint-desktop`, and three `$shadow-*` depths), `_mixins.scss` (theme-transition/reduced-motion/focus-ring/font-smoothing/card-surface/tooltip-arrow — the non-print, non-button shared patterns), `_print.scss` (the link-URL print reveal plus the print-tier mixins: `grid-print-tiers`/`linear-print-tiers`/`compact-print-tiers`/`application-print-tier`, plus `desktop-and-grid-print`/`condensed-print-tiers`/`print-hidden`/`ellipsis-ink` built on top of them — see [components/PRINT-OPTIONS.md](components/PRINT-OPTIONS.md)), and `_buttons.scss` (button chrome, including the shared `.dismiss-button` class). Any component that needs a partial's mixins/variables `@use`s it directly (Gatsby bundles every component's compiled CSS into one site-wide stylesheet, so a value/mixin/rule pulled in from several components still lands once in the final output) — `Layout/index.scss` is not a chokepoint components have to route through.
- `_buttons.scss` is used (opt-out via `:not(:where(...))`, hoisted into the `$button-base-exempt` variable so the main ruleset and its `prefers-reduced-motion` counterpart can't drift apart) by every `<button>` except `.dismiss-button` (shared by `.tooltip__dismiss` and `.print-options__dismiss` — each adds it alongside their own BEM class for their per-instance position/size) and `.resume-skills__skill-toggle`. The diamond-bullet `ul`/`li` look in `_typography.scss` is a bare-element default the same way — `Header`'s markerless flex-row lists (`.resume-header__contact`, `.resume-header__links`) opt back out per-`li`/`li` with their own class or `&::before { content: ''; }` (not a shared mixin — `&__contact`'s items carry a class, `&__links`' don't, so the two lists' bullet-suppression selectors sit at different specificity and can't share one abstraction without changing which one wins against `_typography.scss`'s `ul li::before`).
